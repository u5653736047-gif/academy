## 这份文档是干什么的

从需求文档第 2 节抽出"做什么 / 不做什么"，单独成篇。作用是**变更控制基线**：以后想加功能，先回来看这份文档，而不是直接改需求正文。

**规则**：任何超出本清单的功能，必须先在需求文档里记一笔，再改这份文档；不允许在实现阶段"顺手加了"。

## 一、V1 要做

| # | 能力 | 验收标准 | 状态 |
|---|---|---|---|
| S1 | 学生工作区（Electron 桌面应用） | 能在本机启动、能对话、能看到 agent 干活过程 | 【待填】 |
| S2 | 三个工具：检索课程资料 / 读写项目文件 / 执行命令 | 能跑通一次完整的"报错 → 定位 → 改好 → 跑通" | 【待填】 |
| S3 | 多智能体（主 agent + 通用子代理基座 + 资料检索子代理） | 主 agent 能把大任务拆给子代理，子代理只回摘要 | 【待填】 |
| S4 | 权限闸三档 + 审计日志 | 见 [test/permission-cases.md](./test/permission-cases.md) | 【待填】 |
| S5 | 回答有出处 | 引用只来自检索片段，资料没有时明说 | 【待填】 |
| S6 | 一键反馈 | 学生能标记"这个回答不对"，记录到服务端 | 【待填】 |
| S7 | 服务端三件事：知识库 / 检索 / 记录 | 老师能上传资料，学生能检索到 | 【待填】 |

## 二、V1 明确不做

以下内容**已经讨论过并决定推迟**，不要在实现时"顺手做了"：

| # | 不做的事 | 为什么不做 | 什么时候做 |
|---|---|---|---|
| N1 | 作业批改 / 练习模式 | 背后需要一整套标准答案管理方案（答案只许在服务端、怎么防泄漏） | 第二阶段 |
| N2 | 老师工作区（教案 / PPT 制作 / 批改发布） | 在同一个内核上加工具，但前提是学生端先跑通 | 第二阶段 |
| N3 | 转老师队列 | 老师端还不存在 | 待定 |
| N4 | 学情分析 | 第一版只收集记录，不做任何分析 | 第二阶段 |
| N5 | 替老师打分 | **永远不做**。评分是人的事 | — |
| N6 | 服务端模型网关 | 学生自己配 key，服务端不经手模型调用 | — |

## 三、V1 待议（可能砍，取决于目标用户范围）

> **【待决·重要】** 需求文档里写的目标用户是一个班的学生，但当前实际目标用户只有作者本人。
> 如果 V1 只服务自己，下面这些可以砍或延期。**这一节需要拍板后才能冻结基线。**

| # | 能力 | 只服务自己时是否可以砍 | 说明 |
|---|---|---|---|
| C1 | Electron 安装包 + 邀请码激活 + 姓名学号登记 | 可能可以 | 没有第二个学生，也没有账号体系 |
| C2 | 服务端"接入服务"（邀请码 / token 签发） | 可能可以 | 同上 |
| C3 | 记录上报的"学生可查可关" | 可能可以 | 自己看日志文件即可 |
| C4 | 首次使用告知同意 | 可能可以 | 文案给谁看？ |
| C5 | 服务端本身（改成本地目录检索） | 可能可以 | 通道形状不变，只换实现层 |
| C6 | 课程知识库管理界面 | 可能可以 | 自己放文件即可 |

**明确不可砍**（即使只服务自己）：权限闸、审计日志、检索子代理的上下文防火墙。
