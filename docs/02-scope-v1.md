# 第一版范围与阶段划分

> 版本：v0.2 ｜ 状态：草稿 ｜ 日期：2026-09-15
> 上游：[01-requirements.md](./01-requirements.md) ｜ 下游：**所有设计文档**
> 适用阶段：两阶段（本文档是划分阶段的基准）

## 这份文档是干什么的

从需求文档第 2 节抽出"做什么 / 不做什么"，并把它**切成两个交付阶段**。作用是**变更控制基线**：以后想加功能，先回来看这份文档，而不是直接改需求正文。

**规则**：任何超出本清单的功能，必须先在需求文档里记一笔，再改这份文档；不允许在实现阶段"顺手加了"。

---

## 一、第一版 = 两个阶段

**2026-09-15 决定**：第一版不再一次做完，切成两个阶段交付。

| | **阶段一** | **阶段二** |
|---|---|---|
| 一句话 | 把 pi 包装成一个**有 GUI 的桌面应用** | 补全**与课程有关**的能力 |
| 核心意图 | **改造 pi 的 agent 核心**：引入子代理、权限闸等机制 | 检索工具 / 检索子代理 / 服务端知识库 |
| 有没有服务端 | **没有** | 有 |
| 有没有新工具 | **没有**（只用 pi 自带） | 课程资料检索工具 |
| 交付给谁 | **只有我自己** | 一个班的学生 |
| 验收方式 | 见第二节末 | 见第三节末（试点三条指标） |

**为什么这么切**：

阶段一做完的是 **"agent 底座 + 人机界面 + 安全闸"这套通用骨架**。骨架立住了，阶段二往里填"课程"这部分内容，才叫在稳固的地基上砌墙。

反过来先做检索，等于**在一个还不知道能不能用的底座上堆业务**——底座一改，上面的全返工。而且阶段一没有任何业务内容，**失败得快、改得也快**。

> 📌 **每个设计文档头部都标了「适用阶段」**，避免在阶段一误读阶段二的设计。

---

## 二、阶段一要做（P1）

**主题：pi 的 agent 核心改造 + 桌面壳。**

| # | 能力 | 验收标准 | 状态 |
|---|---|---|---|
| P1-1 | 桌面应用骨架：Electron + GUI，能对话、能实时看到 agent 在干什么 | 双击启动、发一条消息、看到流式输出和工具调用过程 | 【待填】 |
| P1-2 | pi 以**内嵌 SDK** 方式跑在主进程 | 不需要装 pi CLI，应用自己起会话 | 【待填】 |
| P1-3 | 工具集 = **pi 自带**（读 / 写 / 执行命令）；**不含检索** | 能跑通一次"报错 → 定位 → 改好 → 跑通" | 【待填】 |
| P1-4 | **多智能体**：主 agent + 通用子代理基座（复用 `pi-subagents`） | 主 agent 能把大任务拆给子代理；子代理只回摘要 | 【待填】 |
| P1-5 | **权限闸三档 + 审计日志** | [test/permission-cases.md](./test/permission-cases.md) 全部用例通过 | 【待填】 |
| P1-6 | 主 / 子代理**走同一道闸**；子代理动作可见、可中止 | 用例 PC-E-06 通过；界面上能指认动作归属 | 【待填】 |
| P1-7 | 多会话：新建 / 切换 / **切换不销毁** / 历史会话恢复 | 关掉应用再打开，历史会话能接着聊 | 【待填】 |
| P1-8 | 模型配置：填自己的 API key（自选供应商） | 换一家供应商也能跑 | 【待填】 |

**阶段一明确不包含**（这些全部属于阶段二）：检索工具、检索子代理、服务端、回答出处、一键反馈的服务端上报。

> ⚠️ **【我的推断·待你确认】** 权限闸（P1-5 / P1-6）算在阶段一里。
> 依据：你说阶段一的"核心意图是改造 pi 的 agent 核心，引入子代理**等机制**"，而权限闸就是我们改造内核的最主要一块。
> 如果它其实该往后放，告诉我，第二节和 ADR-0007 一起改。

### 阶段一的"完成"怎么算【需要你定】

⚠️ **需求文档第 5 节的三条成功指标（活跃人数 / 反馈占比 / 留存）全都依赖服务端和学生群体，阶段一两条都没有。**

所以阶段一需要一套**自己的**验收标准。我的建议如下，**请你确认或改**：

| # | 建议的验收项 | 为什么是它 |
|---|---|---|
| A1 | 我自己每天真的拿它调作业 / 写代码，而不是回去开终端 | 阶段一的目标用户就是我，这是唯一有意义的"有人用" |
| A2 | 权限闸用例表全部通过 | 闸错了等于没有，必须逐条过 |
| A3 | 子代理能跑起来，且它的每个动作都走闸、都能被中止 | 这是"内核改造"成功的判据 |
| A4 | 关掉再打开，历史会话能接上 | 证明磁盘账本可靠，不靠内存 |
| A5 | 从启动到跑完一个任务，全程没碰过命令行 | 证明"桌面应用"这件事真的成了 |

### 阶段一已知的风险（已识别，不是意外）

**子代理在阶段一缺少一个真正的用武之地。**

需求文档给多智能体列的理由里，最硬的一条是"**检索结果太长，让子代理在自己的上下文里消化**"——而检索在阶段二。

所以阶段一的子代理只剩两类用途：

1. 长时、复杂任务的拆分（通用基座）
2. 后台任务的可中止性

**这不影响阶段一的价值**——阶段一要验证的本来就是"子代理这套机制能不能接上闸、能不能看见、能不能杀"，而不是"它省了多少 token"。但要有预期：**阶段一的子代理，看起来会有点大材小用。** 真正的收益在阶段二。

## 三、阶段二要做（P2）

**主题：把"课程"装进已经立住的骨架。**

| # | 能力 | 验收标准 | 状态 |
|---|---|---|---|
| P2-1 | 课程资料检索工具（自研扩展 + HTTP，见 [adr/0005](./design/adr/0005-retrieval-tool-extension.md)） | 提问 → 拿回带出处的片段 | 【待填】 |
| P2-2 | **资料检索子代理**（上下文防火墙：只给检索工具 + 只读） | 大段资料在它自己的上下文里消化，只回摘要 | 【待填】 |
| P2-3 | 服务端三件事：知识库 / 检索 / 记录（见 [adr/0003](./design/adr/0003-server-on-rented-vm.md)、[adr/0004](./design/adr/0004-rag-hybrid-retrieval.md)） | 老师传资料，学生能检索到 | 【待填】 |
| P2-4 | **回答有出处**（引用只从检索片段来，资料没有时明说） | 20 道真题人工抽查，引用真实存在 | 【待填】 |
| P2-5 | 一键反馈 | 学生能标记"这个回答不对"，记录到服务端 | 【待填】 |
| P2-6 | 课程激活（邀请码 + 姓名学号） | 拿到本课程的课程工作区 | 【待填】 |
| P2-7 | 打包成安装包 + 分发 | 别的学生能双击装上、不用预装 Node.js | 【待填】 |

### 阶段二的"完成"怎么算

沿用需求文档第 5 节，**试点三条指标**（时长与老师商定，建议 4–6 周）：

1. 每周活跃人数
2. 反馈里"解决了问题"的占比
3. 周留存

**外加一项我们自己加的、不来自需求的**：**出处抽查**——拿 20 道真题跑一轮，人工核对引用是否真实存在于资料中。试点前必须做，不能只靠提示词约束。

## 四、两个阶段都不做

以下内容**已经讨论过并决定推迟或永不做**，不要在实现时"顺手做了"：

| # | 不做的事 | 为什么不做 | 什么时候做 |
|---|---|---|---|
| N1 | 作业批改 / 练习模式 | 背后需要一整套标准答案管理方案（答案只许在服务端、怎么防泄漏） | 阶段二之后 |
| N2 | 老师工作区（教案 / PPT 制作 / 批改发布） | 在同一个内核上加工具，但前提是学生端先跑通 | 阶段二之后 |
| N3 | 转老师队列 | 老师端还不存在 | 待定 |
| N4 | 学情分析 | 第一版只收集记录，不做任何分析 | 阶段二之后 |
| N5 | 替老师打分 | **永远不做**。评分是人的事 | — |
| N6 | 服务端模型网关 | 学生自己配 key，服务端不经手模型调用 | — |

## 五、原"待议"清单的处理结果（2026-09-15）

上一版这一节列了 6 项"只服务自己时可以砍"的能力，**卡着基线不能冻结**。加上阶段划分之后，这 6 项各自有了归宿，**这一节不再是待决项**：

| # | 能力 | 现在归到哪 | 说明 |
|---|---|---|---|
| C1 | Electron **安装包**（分发） | **阶段二** | 阶段一只服务我自己，跑开发模式即可。真正分发在阶段二 P2-7 |
| C2 | 课程激活 + 姓名学号登记 | **阶段二** | 依赖服务端。阶段一没有第二个学生 |
| C3 | 服务端"接入服务"（邀请码 / token） | **阶段二** | 同上 |
| C4 | 记录上报的"学生可查可关" | **阶段二** | 阶段一没有上报这回事 |
| C5 | 首次使用告知同意 | **阶段二** | 阶段一只有我自己用，没有"别人"要被告知 |
| C6 | 服务端本身 | **阶段二** | 阶段一不联任何服务端 |
| C7 | 课程知识库管理界面 | **阶段二** | 同上 |

**为什么"待议"就这么没了**：原来悬着的是"**目标用户只有一个班的学生，还是只有我自己？**"——阶段划分等于回答了一半：

> **阶段一默认只服务我自己；到阶段二才面对学生群体。**
> 而一旦面向学生，上面 7 项的前提就自动成立了，全都得做，一项都砍不掉。

### 两个阶段都必须守住的（不可砍）

| 项 | 阶段 | 为什么不可砍 |
|---|---|---|
| **权限闸** | 阶段一 | 价值就是"我自己不会被 agent 搞坏东西"——我不需要第二个用户，这个价值当下就成立 |
| **审计日志** | 阶段一 | 同上；而且是硬规矩 5（每个动作可见可追溯）的落地 |
| **检索子代理的上下文防火墙** | 阶段二 | 这是多智能体**最硬的那条理由**，不是优化项 |
