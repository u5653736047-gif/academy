## 这份表为什么先于代码存在

权限闸的规则是**纯逻辑**：给定一个工具调用，输出一个判定。这种模块的正确性完全由用例覆盖决定，而不是由实现方式决定。

所以：**先把用例表写出来，再写代码**。写完之后，这张表直接变成测试数据（参数化测试的输入），一行不用改。

## 怎么用

1. 往表里加一行
2. 写代码
3. 跑测试，对着表检查每一条判定

**任何一条用例判定错了，都是 bug——不允许"这条先这样吧"。**

## 表头约定

| 列 | 说明 |
|---|---|
| 用例 ID | `PC-<类别>-<序号>` |
| 档位 | 变更前确认 / 自动审批 / 完全访问 —— **同一动作在不同档位下期望结果不同** |
| 工具 | `bash` / `write` / `edit` / `read` … |
| 输入 | 命令或路径 |
| 期望判定 | 放行 / 拒绝 / 询问 |
| 命中路径 | 白名单 / 黑名单 / 灰区判官 / 档位策略 |
| 备注 | 为什么这么判 |
