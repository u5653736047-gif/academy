## 1. 三条通道

架构文档第 2 节定了三条 HTTP 通道，**除此之外两端互不越界**：

| # | 通道 | 方向 | 载荷 | 时机 |
|---|---|---|---|---|
| ① | 检索 | 本地 → 服务端 → 本地 | 问题 → 相关片段 + 出处 | agent 答题需要资料时，同步 |
| ② | 激活 | 本地 → 服务端 | 邀请码 + 姓名学号 → 课程 token | 首次使用，一次性 |
| ③ | 记录上报 | 本地 → 服务端 | 提问 / 反馈 / 拦截事件 | 异步攒批，可关，学生可查 |

**边界原则**：只有检索工具知道服务端存在；服务端不感知 agent 内部结构（多智能体、子代理数量对它透明）。

### 请求【待填】

```
POST /api/retrieve
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 【待填】 | | | |

### 响应【待填】

```
{
  "chunks": [
    { "text": "...", "source": { "file": "第3章.pdf", "page": 42 }, "score": 0.83 }
  ]
}
```

**必须带出处**（文件名 + 页码）——这是需求"回答有出处"的数据基础。

### 错误码与超时【待填】

| 码 | 含义 | 客户端行为 |
|---|---|---|
| 【待填】 | | |

**超时降级**：决策是"降级为提示"（ADR-0005）。【待决】具体阈值，以及 agent 该怎么跟学生解释。

### MCP 友好格式

按 ADR-0005：接口设计成**无状态**、`query → 片段 + 出处 + 分数`，将来要开放给其他客户端时再包一层 MCP server 壳。

## 3. 通道 ② 激活

```
POST /api/activate
```

请求：邀请码 + 姓名学号 → 响应：课程 token。

- 只用于老师认人，**不做账号密码体系**

## 4. 通道 ③ 记录上报

- 异步攒批、**可关**、**学生可查**
- 上报内容：提问、反馈、拦截事件
- 【待填】批量格式、重试策略、本地队列的持久化

**硬规矩**：发给大模型的请求里**不带学号、姓名**（需求第 4 节硬规矩 3）。
