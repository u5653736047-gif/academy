## 什么是 ADR

一条**已经拍板的、会影响后续所有设计的决定**，一个文件。它记录的不是"我们怎么做的"，而是"**我们为什么这么选，以及放弃了什么**"。

ADR 的价值在于：半年后你回头看，能知道当时为什么不用另一个方案；以及当条件变了，能判断这条决定是否还成立。

## 什么时候写

- 这个决定**影响多个模块**（不是某个函数怎么写）
- 这个决定**不容易改回去**（改回去要推翻一片）
- 存在**看起来也合理的备选方案**（只有一个方案时不算决策）

## 怎么写

1. 复制 [template.md](./template.md)
2. 文件名 `NNNN-短横线小写标题.md`，编号从 0001 起，递增，**不复用**
3. 状态只能填这四种之一：

| 状态 | 含义 |
|---|---|
| 提议中 | 有人在推，还没拍板。**不能据此开工** |
| 已接受 | 拍板了，生效 |
| 已废弃 | 曾经生效，现在不成立了（写清被哪条取代） |
| 被取代 | 被 ADR-XXXX 取代（保留原文，不删） |

4. **ADR 不修改正文**。改主意就写新的，把旧的标成"被取代"——保留决策的历史，这是 ADR 的意义所在
