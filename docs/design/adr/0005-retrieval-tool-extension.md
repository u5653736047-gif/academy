# ADR-0005：检索通道用自研扩展工具 + HTTP

- 状态：**已接受**
- 日期：2026-09-14
- 决策人：项目组
- 相关：[ADR-0004](./0004-rag-hybrid-retrieval.md)、[ADR-0002](./0002-embed-pi-as-sdk.md)

## 背景

agent 需要一个"检索课程资料"的工具。技术上有两条路：

1. **MCP**（Model Context Protocol）：业界事实标准，生态大
2. **pi 原生扩展工具**：`pi.registerTool()` / `defineTool()`

关键事实：**pi 原生不含 MCP**（官方原话：`It intentionally does not include built-in MCP, sub-agents, permission popups, plan mode, to-dos, or background bash.` —— `packages/coding-agent/docs/usage.md:303`）。要在 pi 里用 MCP，得先装一个 MCP 扩展。

## 决策

**自研扩展工具（`pi.registerTool` / `defineTool`）+ HTTP**，直连自己的服务端。

服务端检索接口按 **MCP 友好格式**设计（无状态、`query → 片段 + 出处 + 分数`），将来要开放给其他客户端时再包一层 MCP server 壳。

超时降级为提示。

## 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **自研扩展工具 + HTTP**（选中） | 零中间层；完全控制返回结构（出处元数据）；服务端接口自己定 | 与 MCP 生态不互通 | — |
| 先装 MCP 扩展再写 MCP server | 生态标准，将来能接别的客户端 | 多一个第三方依赖；pi 的 MCP 支持来自扩展而非核心；沙箱/权限多一层不确定 | 当前只有我们一个客户端，标准化的收益兑现不了 |
| 把知识库同步到本地，用 pi 的 `grep`/`find` 工具 | 不用写检索工具 | **违反硬规矩 4**（标准答案、题库不落学生盘）；且没有语义检索 | 不可接受 |

## 后果

### 正面
- 工具返回结构完全可控：出处（文件名 + 页码）随片段一起回来，需求 5"回答有出处"有了数据基础
- 服务端不感知 agent 内部结构（多智能体、子代理数量对它透明）

### 负面 / 代价
- 服务端接口的形状由我们独断，**没有生态背书**，将来若想开放要补 MCP 壳
- 网络依赖：检索超时要有降级路径（当前决策：降级为提示，让 agent 明说"资料没查到"）

### 需要后续跟进的事
- [ ] 接口契约写进 [server-api.md](../server-api.md)：请求、响应、错误码、超时、重试
- [ ] 超时阈值与降级话术（agent 该怎么跟学生解释"检索不可用"）
- [ ] 服务端不可达时的行为（是拒绝回答，还是明说"资料里没有，以下是我的理解"）

## 什么情况下该重新审视

- 如果将来要把知识库开放给别的客户端（比如老师的备课工具、学校其他课程）
- 如果 pi 官方把 MCP 纳入核心
