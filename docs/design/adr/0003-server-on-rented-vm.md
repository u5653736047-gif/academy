# ADR-0003：服务端部署在自租云主机

- 状态：**已接受**
- 日期：2026-09-14
- 决策人：项目组
- **适用阶段：阶段二**（阶段一不联任何服务端）
- 相关：[architecture.md](../architecture.md)、[ADR-0004](./0004-rag-hybrid-retrieval.md)

> 📌 **本决策属于阶段二。** 决策本身已接受、不失效，但**阶段一不据此开工**。
> 阶段划分见 [02-scope-v1.md](../../02-scope-v1.md)。

## 背景

课程资料检索放在服务端而不是同步到学生电脑，理由有三（需求文档第 3 节）：

1. 题库、标准答案只存在服务端，学生本地翻遍磁盘也找不到
2. 老师更新资料立刻生效，不存在"张三的库是上周的版本"
3. 学生端零维护

所以必须有一个服务端。问题是怎么部署。

## 决策

**部署在自己租用的云主机上**，单机 + SQLite 单库。

运维要点：
- HTTPS 用 Let's Encrypt
- SQLite 定期备份
- 防火墙只开必要端口

## 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **自租云主机**（选中） | 完全可控、成本低、SQLite 单文件便于备份 | 运维要自己做（证书、备份、安全更新） | — |
| Serverless（云函数 + 托管数据库） | 免运维、按量计费 | 冷启动影响检索延迟；向量索引放不进函数；成本不透明 | 检索是同步调用，对延迟敏感 |
| 托管向量数据库（Pinecone 等） | 免运维向量检索 | 额外费用；数据出境/合规不确定性 | 单班量级用不上 |
| 本地跑（不分服务端） | 最简单 | 与"标准答案不落学生盘"的硬规矩冲突 | 违反硬规矩 4 |

## 后果

### 正面
- 单机 SQLite 足够支撑单班量级（见 ADR-0004）
- 备份就是复制文件

### 负面 / 代价
- 运维责任在自己：证书续期、系统更新、备份验证、监控
- 单点故障：主机挂了试点就停摆
- 需要自己处理"学生 token 泄露"这类安全问题

## 什么情况下该重新审视

- 试点规模超出一个班（比如全校推广）→ 单机 SQLite 会成为瓶颈
- 学校要求数据必须在校内网络 → 改为校内服务器
