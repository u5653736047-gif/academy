# ADR-0001：本地端采用 Electron 桌面应用

- 状态：**已接受**
- 日期：2026-09-14
- 决策人：项目组
- **适用阶段：阶段一**
- 相关：[architecture.md](../architecture.md)、[ADR-0002](./0002-embed-pi-as-sdk.md)

## 背景

需求文档第 2 节要求学生端"双击即用"。学生电脑上不能假设预装了 Node.js。同时 agent 需要读写本地文件、执行命令，所以必须有真正的本地进程，不能是纯网页。

原方案（需求 v0.2）是 npm 包分发，被否决。

## 决策

本地端做成 **Electron 桌面应用**：渲染进程承载 GUI，主进程承载服务层（agent 宿主）。以**安装包**分发，自带运行时，学生电脑无需预装 Node.js。

## 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| **Electron 桌面应用**（选中） | 自带运行时、跨平台、GUI 生态成熟、主进程可直接跑 Node | 安装包体积大（百 MB 级）、内存占用高 | — |
| npm 包 + 命令行 | 体积极小、开发快 | **要求学生预装 Node.js 和 Git Bash**，对非计算机专业学生是门槛 | 需求要求"双击即用" |
| 纯网页 + 本地代理 | 无需安装 | 仍需装本地代理，"网页 + 代理"两套东西更难解释；浏览器沙箱限制多 | 复杂度更高 |
| Tauri | 体积小 | 后端是 Rust，与 pi（TypeScript）集成需要跨语言桥 | 自研成本高 |

## 后果

### 正面
- 学生侧零环境要求
- 主进程是完整 Node 环境，`pi` 可以 SDK 内嵌（见 ADR-0002）
- GUI 可以用任意前端技术栈

### 负面 / 代价
- **安装包体积**：Electron 运行时 + pi 依赖，预计不小
- **Windows 上的 bash 依赖仍未解决**：pi 的 `bash` 工具在 Windows 上硬找 Git Bash（`C:\Program Files\Git\bin\bash.exe` 或 PATH 上的 `bash.exe`），找不到就报错。见 [ops/build.md](../../ops/build.md)
- 打包复杂度：ESM 入口、asar 中需要 unpack 的运行时资源

### 需要后续跟进的事
- [ ] 实测 Electron 内置 Node 版本是否满足 pi 的 `engines` 要求（Node >= 22.19）
- [ ] 决定 bash 依赖怎么解决：要求学生装 Git for Windows，还是打包一个 bash 进去
- [ ] 打包体积实测

- 如果 Electron 打包遇到无法绕过的技术障碍（如原生依赖）
