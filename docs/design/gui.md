## 3. 四个视图

**阶段一要做其中三个 + 设置的一半**（见下表）。技术栈选型是**阶段一的第一个岔路口**（见第 2 节）。

| 视图 | 阶段 | 说明 |
|---|---|---|
| 3.1 对话视图 | **一**（出处卡片、一键反馈 = 二） | 阶段一最核心的界面 |
| 3.2 会话中心 | **一** | 多会话与历史恢复 |
| 3.3 权限中心 | **一** | 本阶段最复杂的一块 |
| 3.4 激活与设置 | 设置部分**一**；激活向导、告知同意 = 二 | |

### 3.1 对话视图【阶段一】

- 消息流 + 流式渲染
- **子代理过程树**（实时可见，可展开）
- **出处卡片**（资料名 + 页码；点击可看片段原文）——**【阶段二】**
- 一键反馈（回答不对时）——**【阶段二】**
- 权限确认弹窗（见 3.3）——**【阶段一】**

【待填】消息的数据结构、流式渲染的增量协议、过程树的层级表示

### 3.2 会话中心【阶段一】

- 会话列表（空闲 / 运行中 / 待确认）
- 历史会话入口（`pi -r` 的界面化）
- 新建 / 切换（**切换不销毁实例**）

【待填】列表项的字段、状态如何反映主进程真实状态

### 3.3 权限中心【阶段一】

- 三档设置（默认：变更前确认）
- **确认弹窗** —— 要能显示：
  - 谁在请求（`actor`：主 agent / 哪个子代理）
  - 请求什么（工具名 + 参数；`bash` 要显示完整命令）
  - 为什么问（命中黑名单？灰区判官判为危险？）
  - 选项：允许 / 拒绝 /（可能）本次会话内总是允许
  - **倒计时**（超时 = 拒绝，见 permission-gate.md 第 10 节）
- 动作日志（全部可追溯）

【待填】弹窗的三种来源形态（主 agent / 子代理 / 灰区判官）、多个请求排队时的展示

### 3.4 激活与设置

| 内容 | 阶段 |
|---|---|
| API key 配置（学生自选供应商） | **一** |
| 课程工作区目录展示 | **一** |
| 激活向导（邀请码 + 姓名学号） | 二（依赖服务端） |
| 告知同意（首次） | 二（阶段一只有我自己用） |

## 4. 关键交互约定

| 场景 | 行为 |
|---|---|
| agent 正在干活 | 实时显示在读哪个文件、跑什么命令 |
| 弹窗超时 | 按拒绝处理 |
| 学生中止 | 能中止主 agent 或**指定某个子代理** |
| 子代理动作 | 与主 agent 一样可见、可中止 |
| 引用出处 | 只显示来自检索片段的出处；资料没有时显示"资料里没有，以下是模型的理解" —— **【阶段二】** |

## 5. 与权限闸的接口

GUI 不直接调用闸。所有审批经 `ApprovalService` → IPC（见 [ipc-contract.md](./ipc-contract.md)）。

**要求**：GUI 崩溃或卡住时，闸的行为必须是**拒绝**而不是挂起或放行。
