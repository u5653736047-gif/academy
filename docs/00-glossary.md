> 版本：v0.2 ｜ 状态：草稿 ｜ 日期：2026-09-15
> 上游：[02-scope-v1.md](./02-scope-v1.md) ｜ 下游：本目录下所有文档

这份表是为了解决一个问题：需求文档和架构文档里"实例/会话/子代理/工作区"这些词是混着用的，中英文也混着用。**写代码之前把词钉死，否则歧义会变成 bug。**

约定：中文文档里首次出现时写"中文（English）"，之后统一用中文；代码里的标识符统一用英文。

## 〇、贯穿全库的两个词

| 术语 | 含义 |
|---|---|
| **阶段一** | 第一版的第一个交付阶段：把 pi 包装成有 GUI 的桌面应用（内核改造 + 子代理 + 权限闸）。**没有服务端、没有检索** |
| **阶段二** | 第一版的第二个交付阶段：补全检索工具、检索子代理、服务端知识库。**本文档里凡标 `【阶段二】` 的，阶段一不做** |

⚠️ **注意与"三段时序"区分**：端云图底部画的"时序 ①②③"（开课激活 / 日常答疑 / 期末复盘）是**使用生命周期**，不是交付阶段——上一版图里曾把两者都叫"阶段"，已改名。

## 一、pi 内核相关（外部概念，我们不改）

| 术语 | 代码里的对应物 | 含义 |
|---|---|---|
| pi | — | agent 内核项目，本项目的底座。官网 pi.dev |
| pi-agent-core | `@earendil-works/pi-agent-core` | agent 运行时：`Agent` 类、工具调用循环、`beforeToolCall` / `afterToolCall` 钩子 |
| pi-coding-agent | `@earendil-works/pi-coding-agent` | core 之上的一层：`AgentSession`、扩展系统、7 个内置工具、会话存储。**我们主要用这一层** |
| pi-ai | `@earendil-works/pi-ai` | 多供应商大模型接口（OpenAI / Anthropic / Google 等） |
| Agent | `Agent`（pi-agent-core） | 循环本体。持有消息状态与两个钩子字段，钩子是可赋值的公开字段 |
| 工具（tool） | `read` `bash` `edit` `write` `grep` `find` `ls` | pi 内置的 7 个工具。**内置工具本身没有任何路径约束**，闸是唯一防线 |
| 扩展（extension） | `pi.on(...)` / `pi.registerTool(...)` | pi 的插件机制，TypeScript 模块。与 pi 同进程、同权限运行 |
| 扩展事件 | `tool_call` / `tool_result` / `session_start` … | 扩展的挂载点。`tool_call` 是**唯一**的执行前拦截点 |
| ExtensionUIContext | `select/confirm/input/notify/editor` + 25 个其它成员 | 扩展弹对话框的接口。SDK 内嵌时**必须我们自己实现** |
| ResourceLoader | `DefaultResourceLoader` | 扩展的加载器。**扩展不是"创建实例时注入"，而是"随 loader 一起交给实例"** |
| bindExtensions | `session.bindExtensions({ uiContext, mode })` | 让扩展真正生效的一步。**漏了它，闸形同不存在，且不报错** |

## 二、本项目的运行结构

| 术语 | 代码里的对应物 | 含义 |
|---|---|---|
| 本地端 | Electron 应用 | 学生电脑上的桌面应用。渲染进程 = GUI，主进程 = agent 宿主 |
| 服务端 | — | 自租云主机。只做知识库、检索、记录三件事。**【阶段二】** |
| 会话（session） | `AgentSession` 实例 + 一个 JSONL 文件 | 一次持续对话。**落盘的 JSONL 是唯一事实，内存里的实例只是缓存** |
| 实例（instance） | `AgentSession` 对象 | 内存里活着的会话对象。懒创建、切换会话不销毁、空闲 LRU 回收 |
| 实例池 | — | 管理实例生命周期的模块。每会话一实例 |
| 会话装配器 | — | 从 JSONL 读账本 → 重组上下文 → 构造实例。也是"历史会话入口"的数据源 |
| 事件总线 | — | 把实例事件流推给 GUI 的模块；`steer` / `abort` 等指令的落点 |
| 主 agent | 主会话 | 直接面对学生的那个 agent |
| 子代理（subagent） | 独立 `AgentSession` | 独立上下文的 agent，由主 agent 委派任务。**前台跑在父进程内，后台跑在独立进程里（混合模型），见 ADR-0006** |
| 通用子代理基座 | — | 能力完整的子代理定义。专用子代理 = 基座 + 工具限制 + 提示词聚焦 |
| 课程工作区 | 工作目录 | 课程激活后拿到的本地目录。**【阶段二】** |
| 课程知识库 | 服务端存储 | 老师上传的教材 / 课件及其索引。**【阶段二】** |

## 三、权限闸（本项目核心复杂度所在）

> 📌 2026-09-15 修正：本模块**不再是"自研"**——按 [ADR-0007](./design/adr/0007-permission-gate-hook-point.md)，判定引擎**复用社区扩展**，我们负责审批链路与界面。

| 术语 | 英文 | 含义 |
|---|---|---|
| 权限闸 | permission gate | 拦截每一次工具调用、决定放行/拒绝/询问的模块。**挂点是扩展层的 `tool_call` 事件，见 ADR-0007** |
| 复用包 | `@gotgenes/pi-permission-system` | 提供判定引擎的社区扩展（规则匹配、命令解析、路径归一化）。**它的能力边界还没摸清** |
| 三态 | allow / ask / deny | 闸的判定结果。pi 原生只有"过/拦"二态，"询问"要我们自己实现 |
| 三档 | permission tier | 学生可切换的三个档位：变更前确认（默认）/ 自动审批 / 完全访问 |
| 白名单 | allowlist | 命中即放行的规则。项目目录内常规读写、常见安全命令 |
| 黑名单 | denylist | 命中即询问的规则。大面积删除、出项目目录、联网、装全局包 |
| 灰区判官 | gray-zone judge | 黑白名单都没命中时，用一个小模型判危险系数。**拿不准 = 危险** |
| 审批请求 | approval request | 闸发给 GUI 的询问消息（不是函数调用），带 `actor` 标明是谁在请求 |
| 审批排队 | arbiter | 把并发的审批请求串行化的组件。**pi 不做任何 UI 序列化，主/子弹窗会互相覆盖，所以必须自己排队** |
| 批准记忆 | approval memory | 对某个动作的"记住这次允许"。粒度要"窄且可编辑" |
| 审计日志 | audit log | 所有工具动作落盘可查。**档位决定要不要先问，不决定要不要告诉你** |
| 启动自检 | startup self-check | 启动时断言"闸真的装上了"。**扩展加载失败是静默的，不自检就等于裸奔** |

## 四、资料与检索【均属阶段二】

| 术语 | 含义 |
|---|---|
| 检索工具 | 自研扩展工具。把问题发到服务端，拿回带出处的资料片段 |
| 片段 | 检索返回的一段资料内容，自带出处元数据 |
| 出处 | citation。文件名 + 页码。**只许从检索片段里引用，不许模型凭空报页码** |
| 混合检索 | 向量检索 + FTS5 关键词检索，两路结果合并去重 |
| 标准答案 / 题库 | 只存服务端，不落学生磁盘 |

## 五、工程流程

| 术语 | 含义 |
|---|---|
| ADR | Architecture Decision Record，架构决策记录。一条决策一个文件 |
| 追溯矩阵 | 需求 ↔ 设计模块 ↔ 测试用例的对应表 |
| 基线冻结 | 文档定稿后进入的状态，改动需走变更记录 |
| 设计评审 | 设计阶段收尾时对全部文档过一遍，通过后冻结基线 |
| spike（技术验证） | 为了验证"这条路走不走得通"而写的一次性小实验。**用完就扔，不进入产品代码** |
| fail-closed | 出错时默认"拒绝/阻断"，而不是默认放行。本项目闸的核心原则 |
| fail-open | 出错时默认放行。**本项目明确避免的行为** |
| 供应链锁定 | 第三方依赖锁精确版本（不用 `^` / `~`），防止上游突变更改行为 |
